**1-1 使用提取符(<<)可以输出各种基本数据类型的变量的值，也可以输出指针值。**
- **答案：T (正确)**
- **解析：** 在C++中，`<<` 是流插入运算符（虽然题目中称其为“提取符”在术语上可能有误，通常 `>>` 称为提取符，`<<` 称为插入符，但结合“输出”这一功能描述和 `<<` 符号来看），它可以配合 `cout` 输出各种基本数据类型（如 `int`, `float`, `char` 等），也可以直接输出指针变量存储的地址值。

**1-2 可以使几个不同类型的变量共用同一段存储单元。**
- **答案：T (正确)**
- **解析：** 这是 C/C++ 中**共用体（union）**的特性。在 `union` 中，所有成员从同一个地址开始存储，从而达到多个不同类型变量共用同一段内存的目的。

**1-3 使用new运算符开辟存储空间后，不必使用delete运算符撤销相应的空间。**
- **答案：F (错误)**
- **解析：** 在 C++ 中，使用 `new` 动态分配的内存必须手动使用 `delete` 进行释放。如果不释放，会导致**内存泄漏**，程序运行久了可能会耗尽系统资源。

**1-4 函数的形参与实参结合的两种方式（传值、传址），其本质区别在于形参与实参结合时，是否在内存空间临时的创建新的内存区域并进行赋值操作。由此，也引发了两种参数结合方式各自的优缺点，例如传值方式，效率较低，但安全性高；传址方式，效率高，但形参可影响实参的值，故安全性欠佳。**
- **答案：T (正确)**
- **解析：** 这是一个标准的关于参数传递方式的描述。
    - **传值：** 拷贝副本，占用额外空间，修改副本不影响原件，所以安全但效率低（尤其是大对象）。
    - **传址（指针/引用）：** 直接操作原件地址，无需大量拷贝，效率高，但形参的改变会反映到实参上，若不小心误改则安全性相对较低。

**1-5 当函数的返回值是数组类型的，传递的是数组第一个元素的地址。**
- **答案：T (正确)**
- **解析：** 在 C/C++ 中，函数不能直接返回整个数组（即不能按值返回数组），通常通过返回指针来实现。当函数逻辑上“返回数组”时，实际上返回的是指向该数组首元素的指针（即地址）。

#### Data_Structure
###### 1. **D (Data Object / Data Elements) —— 数据对象/元素集合**
- **含义：** D 是数据的有限集合。它代表了我们要处理的“东西”本身。
- **类比：** 如果我们要建立一个“家庭”的数据结构，那么 **D** 就是家庭里的成员：爸爸、妈妈、儿子、女儿。
- **特点：** 在计算机中，这些元素可以是整数、字符，也可以是复杂的结构体（如学生信息、网页链接等）。
###### 2. **R (Relationship) —— 关系的有限集合**
- **含义：** R 是定义在集合 D 上的关系的集合。它描述了 D 里的元素之间是怎么连接的、有什么先后顺序。
- **类比：** 仅仅有家庭成员（D）还构不成“家庭结构”，必须有 **R**。比如：
    - 爸爸和儿子之间是“父子关系”；
    - 哥哥和妹妹之间是“兄妹关系”。
- **数学表示：** R 中的每一个关系 r∈Rr∈R 都是从 D 到 D 的一个映射。比如在逻辑结构中：
    - **x,y∈Dx,y∈D**，如果存在关系 <x,y><x,y>，表示 xx 是 yy 的前驱，yy 是 xx 的后继。
    - 
###### 3. 为什么这个定义很重要？（举例说明）
**同样的元素集合 D，如果对应的关系集合 R 不同，就会构成完全不同的数据结构。**
假设我们有一组数字 D={1,2,3}D={1,2,3}：
- **情况 A：线性结构（Linear Structure）**
    - 关系 R={<1,2>,<2,3>}R={<1,2>,<2,3>}
    - **结果：** 这是一个**线性表**（如数组、链表）。1 在 2 前面，2 在 3 前面，像排队一样。
- **情况 B：树形结构（Tree Structure）**
    - 关系 R={<1,2>,<1,3>}R={<1,2>,<1,3>}
    - **结果：** 这是一个**二叉树**。1 是根节点，2 和 3 是它的子节点。
- **情况 C：集合结构（Set Structure）**
    - 关系 R=∅R=∅（空集，元素之间没有任何关系）
    - **结果：** 这是一个单纯的**集合**，元素之间是松散的。
###### 4. 总结
- **D 是“肉体”：** 存储的具体数值。
- **R 是“灵魂/骨架”：** 数据之间的逻辑组织方式。
**Data_Structure = (D, R)** 告诉我们：在研究数据结构时，不能只看存了什么数（D），更要看这些数之间是怎么组织的（R）。这个定义是后续学习**逻辑结构**（线性、树、图）的基础。


**抽象数据类型 (Abstract Data Type, 简称 ADT)** 是数据结构中的一个核心概念，它主要强调**逻辑定义与物理实现相分离** 即 **“定义”与“实现”的分离**。以下是各选项的分析：
- **A. 数据封装 (Data Encapsulation)：**
    - ADT 将数据集合和定义在该数据集合上的一组操作封装在一起，形成一个统一的整体。
- **B. 使用与实现分离 (Separation of Specification and Implementation)：**
    
    - 这是 ADT 的核心。用户只需要知道这个数据类型“能做什么”（功能/接口），而不需要关心它在底层是“怎么做到的”（具体代码实现）。
- **C. 信息隐藏 (Information Hiding)：**
    
    - 与封装和分离相关，ADT 隐藏了内部的具体存储结构和算法细节，只对外暴露接口。这样即使内部实现改变了，外部调用它的程序也不受影响。
- **D. 用例驱动 (Use-Case Driven)：**
    - “用例驱动”通常是**软件工程**或**面向对象设计（OOD/OOA）**中的方法论（比如在 UML 建模中通过用例来确定需求）。它不是抽象数据类型（ADT）本身的基本特征或定义性描述。
